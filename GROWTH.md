# План роста: от Junior+ к уверенному Middle

Цели привязаны к этому проекту, чтобы тренироваться на реальных задачах. У каждой цели есть проверяемый результат: «сделал» или «не сделал», без «стал лучше понимать».

Ориентир по времени: 6–9 месяцев при 5–8 часах в неделю.

---

## Принцип, который важнее всего остального

**Ни одна строка не считается готовой, пока вы не запустили её и не увидели результат.**
Большинство найденных в проекте багов (сломанные эндпоинты, парсинг ×1000) ловились бы за минуту ручным вызовом или одним тестом.

Правило на каждый коммит:
1. Запустил приложение или тест и своими глазами увидел, что работает.
2. Прочитал свой diff целиком (`git diff`) как чужой код.
3. Убрал из diff мусор: пустые классы, закомментированный код, отладочные эндпоинты.

---

## Этап 1 — Дисциплина (месяцы 1–2)

| Цель | Как проверить |
|---|---|
| **Ни одного коммита без запуска.** Перед каждым PR прогнать затронутые эндпоинты через Swagger | в описании PR есть строка «проверено: что именно и как» |
| **Тест на каждый баг**: сначала падающий тест, потом исправление | у каждого `fix:` коммита есть тест, который падал до правки |
| **Подключить авторизацию** на все эндпоинты (Фаза 1 из `ROADMAP.md`) | запрос без токена даёт 401, это проверено тестом на каждый маршрут |
| **Убрать секреты из git**, сменить ключи, читать их из окружения | `git grep` по паролям и ключу пустой, старый JWT-ключ недействителен |
| **Поднять CI** (GitHub Actions: build → test) | красный тест блокирует мерж; зелёная галочка на каждом PR |
| **Работать через ветки и PR**, даже в одиночку | в `main` нет прямых коммитов; PR читается через сутки после написания |

## Этап 2 — Инженерная глубина (месяцы 3–5)

| Цель | Как проверить |
|---|---|
| **Знать, как EF превращает LINQ в SQL.** Включить логирование запросов, разобрать три своих запроса и найти N+1 | можете объяснить, почему `Select(Method)` внутри запроса падает, и показать исправление |
| **Транзакции и согласованность.** Починить создание марки: сохранять термообработки и свойства атомарно | тест: падение на втором шаге откатывает первый |
| **Интеграционные тесты на реальном PostgreSQL** (Testcontainers) | прогон миграций с нуля в тесте; тест уникального индекса |
| **Безопасность.** Пройти OWASP Top 10 по своему API: что из списка у вас воспроизводимо | список находок с исправлениями; rate limit и lockout на `/login` |
| **Читать чужие логи.** Находить причину сбоя по логам и метрикам Grafana, не по догадкам | сломать сервис намеренно и найти причину за 10 минут только по логам |
| **Асинхронность.** Объяснить, что делает `await`, чем плох `.Result`, зачем `CancellationToken` | короткий разбор своих хендлеров, найти места без `ctn` |

## Этап 3 — Проектное мышление (месяцы 6–9)

| Цель | Как проверить |
|---|---|
| **Довести фичу «от идеи до продакшена»**: база знаний (Фаза 3) целиком, с тестами, миграциями, документацией | фича работает на стенде, у неё есть README и тесты |
| **Писать мини-дизайн-документ** на решение (одна страница: проблема, варианты, выбор, цена) | три документа в `docs/`: ML-сервис, база знаний, авторизация |
| **Уметь объяснить свой выбор**: почему gateway, почему отдельная БД Identity, когда это лишнее | устный разбор на 5 минут без бумажки; честно назвать минусы |
| **Принимать ревью.** Попросить опытного человека посмотреть PR и разобрать замечания | хотя бы 5 PR с содержательными комментариями от другого человека |
| **Оценка сроков.** Оценивать задачу заранее и сверять с фактом | таблица «оценка / факт» по 10 задачам; ошибка со временем сокращается |

## Что читать и смотреть

Немного, но по делу.

- «Clean Code» не обязательна. Важнее: документация EF Core (Querying, Change Tracking), «Designing Data-Intensive Applications» (главы 1–3 и 7).
- OWASP Top 10 и OWASP ASVS (уровень 1) как чеклист.
- Блог Andrew Lock про ASP.NET Core, документация Microsoft по Minimal APIs, Options, HttpClientFactory.
- Для тестов: Vladimir Khorikov, «Unit Testing Principles, Practices, and Patterns».

## Практика поверх проекта

- **Раз в неделю** читать код одной чужой open-source библиотеки, которую уже используете (MediatR, FluentValidation, Refit). Двадцать минут, и можно вынести два-три приёма.
- **Раз в две недели** делать «день долга»: убирать мусор, закрывать заглушки, переименовывать опечатки.
- **Раз в месяц** ломать свой проект: убить контейнер БД, выключить Redis, подать мусор в API. Смотреть, что происходит и можно ли понять причину.
- **Задавать вопросы вслух.** Если не можете за минуту объяснить, как работает ваш код, значит, вы его не понимаете, а не запомнили.

## Критерии «норм разработчик»

Вы на уровне, когда одновременно верно следующее:

1. Ваши PR редко содержат баги, видимые при первом запуске.
2. Любое изменение имеет тест, а CI блокирует регрессии.
3. Вы можете выпустить сервис наружу и не бояться: авторизация, секреты, лимиты, бэкапы, мониторинг на месте.
4. Вы сами находите причину сбоя по логам и метрикам.
5. Вы объясняете свои решения и их цену, а не только «так делают».
6. Вы принимаете критику ревью без обороны и делаете выводы.
